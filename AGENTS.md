# Agent Guidelines — Portfolio & CV (Gilles Crieloue)

This guide documents the critical architecture, styling patterns, print export mechanics, and strict project constraints for agents working on this codebase.

---

## 1. Core Identity & Editorial Constraints

- **Name spelling**: Always use **`Gilles Crieloue`** (strictly no accent on the 'e' — do not write _Crieloué_).
- **Blog article dates**: **Never include the year** in article date displays (e.g., write `12 oct.`, never `12 oct. 2026`).
- **Aesthetic**: Minimalist, monochrome, editorial style. Off-white (`#fafafa`) on web, pure crisp white (`#ffffff`) in print. Clean hairline dividers over heavy boxed borders.

## 3. Framer Motion vs CSS Transitions (Critical Rule)

> [!WARNING]
> **Never apply CSS `transition: all` to any component animated by Framer Motion.**

- **The Pitfall**: When an element animated with `motion.*` (e.g. `motion.article`, `motion.div`) has a CSS `transition: all` rule, the CSS transition engine intercepts inline styles generated by Framer Motion on every frame (`requestAnimationFrame`). This causes:
  - Severe visual blinking / flashing upon scroll entry or hydration.
  - Jittery, fighting animations during translateY translations.
- **The Solution**: On interactive cards like `.card-minimal`, scope CSS transitions exclusively to properties that change on `:hover`:
  ```css
  .card-minimal {
    transition:
      border-color 0.25s cubic-bezier(0.16, 1, 0.3, 1),
      box-shadow 0.25s cubic-bezier(0.16, 1, 0.3, 1);
  }
  ```
- **Recommended Scroll Entry Animation**:
  ```tsx
  initial={{ opacity: 0, y: 24 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: "0px 0px -40px 0px" }}
  transition={{ duration: 0.8, delay: 0.05, ease: [0.16, 1, 0.3, 1] }}
  ```
  _Note_: The bottom margin `-40px` ensures the animation triggers after the element enters the visible screen area, rather than popping at the 0px boundary.

## 4. Print & PDF Export Rules (`@media print`)

The portfolio features a direct browser PDF export (`Cmd + P` or the print button in the header).

### A. Framer Motion Override

Elements using Framer Motion mount with inline `opacity: 0` before scrolling. In print, scrolling does not happen, which renders elements below the fold invisible (resulting in blank pages). Always enforce visibility in `@media print`:

```css
@media print {
  *,
  *::before,
  *::after {
    opacity: 1 !important;
    transform: none !important;
    filter: none !important;
  }
}
```

### B. Avoiding Box & Border Clutter ("Bordures dans des bordures")

- In print, avoid enclosing every section, card, and pill tag inside nested borders.
- Keep `.tag` pills borderless and minimal in print.
- Format skills as clean typographic inline lists (`Langages : Java • Kotlin • TypeScript...`).
- Separate work experiences with a single top hairline divider (`border-t border-zinc-200`) rather than 4-sided boxed cards.

### C. Page Break & Pagination Architecture

- **Page 1 (Executive Summary)**: Dedicated single-page overview (Contact Header, À propos, Compétences & Langues, Formation & Certifications).
- **Page 2+ (Work Experiences)**: Section `#experience` uses `print:break-before-page` so experiences start cleanly on page 2.
- **Orphan Headings Prevention**:
  ```css
  h1,
  h2,
  h3,
  h4,
  h5,
  h6,
  [data-title],
  .print-break-after-avoid {
    break-after: avoid !important;
    page-break-after: avoid !important;
  }
  ```
- **Native Browser Headers/Footers Trap**: Never attempt to remove browser headers (date, URL) with `@page { margin: 0 }`, as this strips all physical page margins and pushes text to the physical edge of the paper. Browser headers/footers must be unchecked once by the user in the print dialog.

## 5. Collapsing Header & Scroll Stability Architecture

### A. Preventing Mobile Scroll Oscillation / Jitter Loop

> [!CAUTION]
> **Never dynamically shrink or grow an element in the normal document flow based on `window.scrollY`.**

- **The Pitfall**: When a `sticky top-0` header collapses by $\Delta h$ (e.g. from 185px to 99px, $\Delta h = 86px$):
  - On mobile touch devices, the touch gesture is anchored to the touched element in `<main>`.
  - When the header shrinks, `<main>` shifts up by 86px, which pulls `window.scrollY` backwards below the trigger threshold.
  - The header expands back, pushing `<main>` down, triggering the collapse threshold again.
  - This creates an uncontrollable 60fps flapping / jitter loop near the scroll boundary.
- **The Solution**:
  1. Position the animated header as `fixed top-0 left-0 right-0 z-50`.
  2. Keep an invisible, non-interactive placeholder (`aria-hidden="true"`, `print:hidden`) in the normal document flow with the exact expanded height.
  3. Because the placeholder in document flow **never changes height**, collapsing or expanding the header produces **0px layout shift** ($\Delta h = 0$), guaranteeing total scroll stability.
  4. Always add `whitespace-nowrap` to inline collapsible spans (e.g. `/ Senior Full-Stack`) so that `max-w-0` does not cause invisible text to wrap into a multi-line vertical column that alters the line height.
  5. Use dual-threshold hysteresis ($T_{\text{collapse}} = 80px$, $T_{\text{expand}} = 25px$) throttled via `requestAnimationFrame`.
